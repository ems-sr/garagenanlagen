## Project

Next.js 16 (App Router) app generated by `create-prisma` with the Next.js + Prisma Next + shadcn template. Package manager is pnpm; run all commands with `pnpm`, not `npm`/`yarn`.

## Commands

- `pnpm run dev` — start local dev server
- `pnpm run build` — production build
- `pnpm run start` — run production server
- `pnpm run lint` — eslint

### Database (Prisma Next)

- `pnpm run contract:emit` — regenerate `prisma/contract.json` / `prisma/contract.d.ts` after editing `prisma/contract.prisma`
- `pnpm run db:init` — create tables in the database from the contract
- `pnpm run db:update` — update database state to match the contract
- `pnpm run db:verify` — verify database state matches the contract
- `pnpm run db:seed` — run `tsx prisma/seed.ts` to insert sample data
- `pnpm run migration:plan` — create a migration plan
- `pnpm run migrate` — apply a planned migration
- `pnpm run migration:status` / `pnpm run migration:show` — inspect migrations

There is no test runner configured in this project yet.

## Architecture

This is **Prisma Next** (not classic Prisma ORM — different APIs, do not confuse the two; see the `prisma-8` skill for reference docs). Key pieces:

- `prisma/contract.prisma` — the data contract; source of truth for all models. Edit this to add/change models.
- `prisma/contract.json` / `prisma/contract.d.ts` — generated from the contract via `pnpm run contract:emit`. Commit both; never hand-edit them.
- `prisma-next.config.ts` — CLI config; points at the contract and reads `DATABASE_URL` from `.env` via `dotenv/config`.
- `prisma/db.ts` — the query client: `import { db } from '@/prisma/db'`, then e.g. `db.orm.User.where({ email }).first()`. Types are fully inferred from the contract.
- Requires PostgreSQL 17+; connection string lives in `.env` (`DATABASE_URL`), copy from `.env.example`.

Frontend: standard Next.js App Router under `app/`, Tailwind CSS v4 (via `@tailwindcss/postcss`, imported with `@import "tailwindcss"` in `app/globals.css`), shadcn/ui components under `components/ui` (style `base-vega`, Phosphor icon library, path aliases `@/components`, `@/lib`, `@/hooks`, `@/components/ui` — see `components.json`). Use the `shadcn` skill when adding/modifying shadcn components.
